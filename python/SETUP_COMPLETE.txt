## 🎯 TL;DR - THE ESSENTIALS

### For LOCAL Building & Publishing:

1. Install tools:
   ```bash
   pip install maturin twine
   ```

2. Get PyPI token:
   - https://pypi.org/manage/account/ → API tokens
   - Copy the token (starts with pypi-)

3. Configure ~/.pypirc:
   ```bash
   cp python/.pypirc.template ~/.pypirc
   nano ~/.pypirc  # Add your token
   chmod 600 ~/.pypirc
   ```

4. Build & publish:
   ```bash
   cd python
   ./build_wheels.sh
   ./publish_wheels.sh
   ```

### For GITHUB ACTIONS (Automated):

1. Get PyPI token (same as above)

2. Add to GitHub:
   - Go to: Settings → Secrets and variables → Actions
   - New secret: Name=`PYPI_TOKEN`, Value=(your token)

3. Trigger:
   - Create a release on GitHub, OR
   - Actions → Build Binary Wheels → Run workflow

## 🔐 WHERE EACH SECRET/TOKEN GOES

┌───────────────────┬────────────────────────────────────────────────────┐
│ Location          │ What Goes There                                    │
├───────────────────┼────────────────────────────────────────────────────┤
│ PyPI.org          │ • Your account                                     │
│                   │ • 2FA enabled                                      │
│                   │ • API token generated (source of truth)            │
│                   │   Token looks like: pypi-AgEIcHlwaS5vcmcCJ...     │
├───────────────────┼────────────────────────────────────────────────────┤
│ ~/.pypirc         │ • Local machine config file                        │
│ (your computer)   │ • Password field = your PyPI token                 │
│                   │ • Permissions must be 600                          │
│                   │ • Used by: twine upload (local publishing)         │
├───────────────────┼────────────────────────────────────────────────────┤
│ GitHub Secrets    │ • Secret name: PYPI_TOKEN                          │
│ (repository)      │ • Secret value: your PyPI token (same as above)    │
│                   │ • Path: Settings → Secrets → Actions               │
│                   │ • Used by: GitHub Actions workflow                 │
└───────────────────┴────────────────────────────────────────────────────┘

⚠️ IMPORTANT: Same token in TWO places (local + GitHub)

## ❓ COMMON QUESTIONS

Q: Do I need BOTH local setup AND GitHub setup?
A: No. Choose one:
   - Local only: Setup ~/.pypirc, run ./publish_wheels.sh
   - GitHub only: Setup secrets, create releases
   - Both: Maximum flexibility

Q: What's the difference between PYPI_TOKEN in GitHub vs ~/.pypirc?
A: Same token, different locations:
   - ~/.pypirc: For local publishing with twine
   - GitHub secret: For automated GitHub Actions
   They can (and should) be the same token.

Q: Do I need TestPyPI?
A: Recommended but optional. It's a safe testing environment.
   Practice there first before publishing to production PyPI.

Q: What if I don't want to publish publicly?
A: See ENVIRONMENT_SETUP.md for private package index options:
   - AWS CodeArtifact
   - Google Artifact Registry
   - Azure Artifacts
   - Gemfury
   - Self-hosted

Q: How do I know if everything is set up correctly?
A: Run: `./check_environment.sh`
   Should see all green checkmarks.

Q: Can I see my GitHub secrets after adding them?
A: No, GitHub hides secret values for security.
   You can only see that they exist (by name).

Q: What if I lose my PyPI token?
A: Create a new one:
   1. Go to PyPI account settings
   2. Delete old token
   3. Create new token
   4. Update ~/.pypirc
   5. Update GitHub secret

## 🐛 TROUBLESHOOTING

Problem: "Invalid authentication credentials"
Solution:
  1. Check ~/.pypirc has correct format
  2. Verify token starts with `pypi-`
  3. Ensure no extra spaces or quotes
  4. Verify token is for correct PyPI (not TestPyPI)
  5. Check token hasn't expired or been deleted

Problem: "Package already exists"
Solution:
  1. Can't overwrite published versions (PyPI security)
  2. Bump version in pyproject.toml
  3. Rebuild and republish

Problem: "GitHub Actions workflow fails"
Solution:
  1. Check Actions tab for error message
  2. Verify PYPI_TOKEN secret exists
  3. Verify secret name is exactly: PYPI_TOKEN (all caps)
  4. Check workflow YAML syntax (indentation)

Problem: "./build_wheels.sh: command not found"
Solution:
  ```bash
  chmod +x python/build_wheels.sh
  cd python && ./build_wheels.sh
  ```

Problem: "Rust source found in wheel!"
Solution:
  This shouldn't happen with provided scripts.
  Check MANIFEST.in and rebuild.
